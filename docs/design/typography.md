# Typography Rules

> 프로젝트에 관계없이 동일하게 적용되는 타이포그래피 규칙.
> 폰트가 바뀌어도, 플랫폼이 바뀌어도 이 규칙은 그대로 사용한다.

---

## 1. 단위: pt

iOS에서 **1pt = 1 논리적 픽셀**. 기기 배율에 따라 물리 픽셀이 달라진다.

| 기기 | 배율 | 1pt |
| --- | --- | --- |
| 구형 iPhone | @1x | 1px |
| iPhone SE 등 | @2x | 2px |
| iPhone 15 Pro 등 | @3x | 3px |

React Native의 `fontSize: 17`은 곧 17pt이다.

## 2. Type Scale — 크기 산출

### 원리

**하나의 기준 크기(base)**에 **일정한 비율(ratio)**을 반복 곱/나눗셈하여 위계를 만든다.

```
... ÷ ratio²  ÷ ratio¹  ←  base  →  × ratio¹  × ratio² ...
```

### Scale 비율표 (음악 음계 기원)

| 비율 | 이름 | 느낌 | 적합한 곳 |
| --- | --- | --- | --- |
| 1.125 | Major Second | 차분, 균일 | 데이터 대시보드, 생산성 |
| **1.200** | **Minor Third** | **균형잡힌 표준** | **대부분의 모바일 앱** |
| 1.250 | Major Third | 명확한 위계 | 뉴스, 콘텐츠 |
| 1.333 | Perfect Fourth | 드라마틱 | 마케팅, 랜딩 |
| 1.500 | Perfect Fifth | 매우 극적 | 포스터, 히어로 섹션 |

> **모바일에는 1.2(Minor Third) 권장.**
> 화면이 좁아서 비율이 크면 제목이 공간을 낭비하고, 작으면 위계가 안 보인다.

### 산출 예시 (base=17, ratio=1.2)

```
caption  = 17 ÷ 1.2¹   = 14.2  → 13 (HIG 스냅)
sub      = 17 ÷ 1.2⁰·⁵  = 15.5  → 15 (HIG 스냅)
body     = 17            = 17    (기준)
heading  = 17 × 1.2¹   = 20.4  → 20 (HIG 스냅)
title    = 17 × 1.2²   = 24.5  → 28 (HIG Title1에 스냅)
```

최종 값은 순수 계산값이 아니라, **scale로 대략적 크기를 잡고 → HIG 또는 짝수에 스냅**한다.

## 3. 라인높이(Line Height) — 역할별 비율

### 원리: 글씨가 클수록 비율은 작아진다

| 크기 | 이유 | 비율 |
| --- | --- | --- |
| 큰 글씨 (20pt+) | 글자 자체가 커서 줄이 명확히 보임. 넓으면 흩어져 보임 | 낮게 |
| 본문 (15~17pt) | 여러 줄을 연속으로 읽으므로 시선 이동이 자연스러워야 함 | 높게 |
| 작은 글씨 (13pt-) | 줄이 붙어 보이기 쉬움. 단, 본문만큼 길게 읽진 않음 | 중간 |

### 역할별 비율 (경험적 표준)

| 역할 | 비율 | 근거 |
| --- | --- | --- |
| 제목 (title, heading) | **1.25** | Bringhurst 권장 디스플레이 텍스트 1.2~1.3 |
| 본문 (body, sub) | **1.4** | WCAG 접근성 권장 최소 1.5, 실무 1.4~1.6 |
| 캡션 (caption) | **1.35** | 작은 글씨에 적절한 여유. HIG Footnote 13/18 = 1.38과 일치 |
| 인용 (quote) | **1.55** | 시/인용구는 의도적 "숨 쉬는 공간" |

> 이 값들은 공식이 아닌 **"이 정도면 잘 읽힌다"는 경험적 범위의 대표값**이다.
> ±0.05 정도는 폰트 특성에 따라 조정 가능.

### 계산 공식

```
lineHeight = ceil(fontSize × ratio / 2) × 2
```

`÷2 ×2`는 짝수 스냅. 결과가 자연스럽게 8pt 그리드에 가까워진다.

검증:

```
title   28 × 1.25 = 35.0  → ceil(35/2)×2   = 36
heading 20 × 1.25 = 25.0  → ceil(25/2)×2   = 26
body    17 × 1.4  = 23.8  → ceil(23.8/2)×2  = 24
sub     15 × 1.4  = 21.0  → ceil(21/2)×2   = 22 (또는 20, 허용 범위)
caption 13 × 1.35 = 17.55 → ceil(17.55/2)×2 = 18
quote   19 × 1.55 = 29.45 → ceil(29.45/2)×2 = 30
```

## 4. 텍스트 간격 — line-height에서 파생

텍스트 블록 사이의 간격은 별도로 정하는 게 아니라 **body의 line-height(LH)에서 비율로 산출**한다.

### 공식

```
LH = body의 lineHeight (예: 24px)

제목 → 본문      LH × 0.33    (한 묶음이므로 가깝게)
문단 내 줄 간     LH × 0       (lineHeight가 자동 처리)
문단 ↔ 문단      LH × 0.5     (줄 간격보다 약간 넓게)
리스트 아이템 간   LH × 0.5     (문단 간격과 동일)
본문 → 다음 제목  LH × 1.0     (맥락 전환 신호)
```

### 검증 (LH = 24)

```
제목-부제:       24 × 0.33 = 8    → 8px
문단 ↔ 문단:    24 × 0.5  = 12   → 12px
리스트 아이템:   24 × 0.5  = 12   → 12px
본문 → 다음 제목: 24 × 1.0  = 24   → 24px
```

### 정리

| 관계 | 비율 | LH=24 기준 |
| --- | --- | --- |
| 제목 ↔ 부제 | × 0.33 | 8px |
| 문단 내 줄 | × 0 | lineHeight가 처리 |
| 문단 ↔ 문단 | × 0.5 | 12px |
| 리스트 아이템 간 | × 0.5 | 12px |
| 본문 → 다음 제목 | × 1.0 | 24px |

## 5. 한글 보정

한글은 라틴 대비 획 밀도가 높고, ascender/descender 차이가 작아 같은 사이즈에서도 답답하게 느껴진다.

### 보정 규칙

1. HIG 라인높이에 **+2pt** 정도를 한글 보정값으로 적용
2. **제목류(20pt+)는 보정 최소화** — 타이트함이 시각적 힘을 만듦
3. **본문류(15~17pt)는 충분히 넓히기** — 장문 가독성이 핵심
4. 최종 값은 반드시 **짝수 스냅** (위 공식이 자동으로 처리)

> Section 3의 비율 자체에 이미 한글 보정이 반영되어 있다.
> 라틴 전용이었다면 본문 비율은 1.3이면 충분하지만, 1.4로 잡은 이유가 한글 보정이다.

### 폰트별 보정 참고

| 폰트 | 특성 | 추가 보정 |
| --- | --- | --- |
| Pretendard | x-height 큼, 라틴 메트릭에 가까움 | 기본 공식 그대로 |
| Noto Sans KR | Pretendard와 유사 | 기본 공식 그대로 |
| Spoqa Han Sans | 라틴 메트릭에 매우 가까움 | 기본 공식 그대로 또는 -1 |
| Hahmlet / 세리프류 | 획이 복잡, 시각적 밀도 높음 | 비율 +0.05 또는 +2pt |

## 6. 위계 표현

크기만으로 위계를 만들지 않는다. **굵기(weight)**와 **색상**을 조합한다.

| 수단 | 효과 | 예시 |
| --- | --- | --- |
| 크기 차이 | 구조적 위계 (제목 vs 본문) | 28pt vs 17pt |
| 굵기 차이 | 같은 크기 내 강조 | regular vs bold |
| 색상 차이 | 중요도/역할 구분 | 주요 vs 보조 vs 비활성 |

> 34pt 이상의 "보여주는 텍스트" (금액, 온도, 타이머 등)는 프리셋 바깥에서 자유롭게 사용 가능.
> 이 경우 라인높이 비율 1.1~1.2 정도로 타이트하게 잡는다.
